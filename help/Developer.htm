urlFido Developer Notes

How urlFido is built, released and laid out. Since 1.2.0 it is built on the Homer Development Kit (HomerDev), kit 1.43.2 or later, in C:\HomerDev.

The project folder

C:\urlFido mirrors the installed tree:

  • At the top: urlFido.cs (the program), build.cmd, urlFido_setup.iss, urlFido.cmd, urlFido.ico, urlFido.png (the 1024-pixel master of the icon), urlFido.wav (the bark), accept.inix, RepoFiles.txt, LocalFiles.txt, ReadMe and License.
  • exec — the built urlFido.exe. Never in git.
  • help — this document and the others: urlFido (the guide), Announce, Developer, History, Hotkeys, each as .md and .htm.
  • logs — one log per run of the build or any tool.
  • scripts — the kit’s tools, refreshed from C:\HomerDev\scripts by every build.
  • work — fetched build inputs: work\nvda\nvdaControllerClient.dll. Never in git.

version.txt holds the version and lives only on this machine. The build writes Version.cs from it, and the installer reads it directly.

The four steps

  1. build — steps the version (build nobump keeps it), compiles exec\urlFido.exe, writes each .htm from its .md, puts the project’s files in the Homer encoding, checks that the installer ships every file in help, and builds urlFido_setup.exe. Its log is logs\urlFido-build-yyyyMMdd-HHmmss.log.
  2. scripts\push "message" — rewrites the whitelist .gitignore from RepoFiles.txt, commits and pushes.
  3. scripts\tidy and scripts\tidy --do-it — the periodic clean.
  4. scripts\release — runs scripts\check, then tags the pushed commit with the version stamped in urlFido_setup.exe and publishes the installer. The published installer is always at the releases page’s latest/download/urlFido_setup.exe.

Try the fresh build with urlFido -g (the urlFido.cmd at the top runs exec\urlFido.exe).

What the build fetches

Nothing is fetched by hand. The build finds the Roslyn C# compiler with vswhere, or installs the free Visual Studio Build Tools with winget. The Framework’s own csc.exe stops at C# 5 and cannot compile the kit. It fetches NVDA’s controller client, 64-bit, from NV Access’s published controllerClient.zip into work\nvda and embeds it; nvdaLoader writes it to %LOCALAPPDATA%\urlFido and loads it only when NVDA is running. It installs pandoc and Inno Setup with winget when they are missing.

The kit’s classes

urlFido compiles eight of them straight from C:\HomerDev\CSharp: Elevate, Inix, Lbc, Log, Paths, Say, Util and Web. The copies of Inix, Lbc, Say, Util and Web that urlFido used to carry are deleted by the build once the kit’s are there; they had drifted from the kit’s. Lbc needs Elevate (its Help box offers the update), Log and Paths, which is why those three are compiled in too.

  • Log keeps the session log in %LOCALAPPDATA%\urlFido\logs. urlFido’s own logger class writes every line to it as well as to the optional urlFido.log, and Main records anything program.run did not catch.
  • Paths.configs() is where urlFido.inix lives.
  • Elevate answers F11, claimed through the dialog’s commandKey.

It drives Edge over the Chrome DevTools Protocol using only .NET Framework classes (System.Net.WebSockets.ClientWebSocket for the connection and System.Web.Script.Serialization.JavaScriptSerializer for JSON), the wire protocol Playwright uses, so urlFido reproduces urlCheck’s browser-driving behavior without a Node.js driver or a bundled browser.

Conventions

  • Camel Type for C#, as C:\HomerDev\help\CamelType_CSharp.md describes. Constants added since the move to the kit carry the c_ prefix.
  • urlFido shares identifier names with urlCheck, extCheck and 2htm: sProgramName, sProgramVersion, sConfigFileName, sLogFileName, sOutputDir, and the logger surface open, close, info, warn, error.
  • The icon is original artwork generated by script; urlFido.ico carries the 16 to 256 pixel sizes and is embedded at build time.
  • “url” is written in lower case throughout, as the guide explains.
